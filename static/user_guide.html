CrystalNexus: A Web-based Crystal Structure Analysis Platform Using CHGNet

Abstract

CrystalNexus is a web-based application for rapid crystal structure analysis utilizing the Crystal Hamiltonian Graph Neural Network (CHGNet). This platform enables materials scientists to perform density functional theory (DFT)-quality predictions of energetic and magnetic properties for crystalline materials within seconds. The application implements structure optimization, element substitution, and supercell generation capabilities while maintaining rigorous validation protocols for input crystallographic data.

1. Introduction

The development of machine learning interatomic potentials has revolutionized computational materials science by enabling rapid predictions of material properties without the computational overhead of traditional density functional theory calculations[1],[2]. Among these approaches, the Crystal Hamiltonian Graph Neural Network (CHGNet) represents a significant advancement in universal neural network potentials for solid-state materials[3].

CrystalNexus leverages CHGNet to provide an accessible web interface for crystal structure analysis, targeting materials researchers who require rapid property predictions for structure screening and optimization tasks. The platform addresses the growing need for efficient computational tools that bridge the gap between high-accuracy quantum mechanical calculations and practical materials discovery workflows.

2. Theoretical Background: CHGNet Algorithm

2.1 Graph Neural Network Architecture

CHGNet employs a graph neural network architecture where crystal structures are represented as undirected graphs $G = (V, E)$, with vertices $V$ corresponding to atoms and edges $E$ representing interatomic interactions[3]. Each atom $i$ is characterized by an initial feature vector $h_i^{(0)}$ encoding atomic number, coordination environment, and local chemical information.

The model utilizes a message-passing framework where atomic representations are iteratively updated through L layers:

$$h_i^{(l+1)} = \text{UPDATE}^{(l)}\left(h_i^{(l)}, \text{AGGREGATE}^{(l)}(\{h_j^{(l)} : j \in N(i)\})\right)$$

where $N(i)$ represents the neighborhood of atom $i$, determined by a distance cutoff radius of 5.0 Å[3].

2.2 Multi-task Learning Framework

CHGNet implements a multi-task learning approach, simultaneously predicting multiple target properties through shared representations. The total loss function is formulated as:

$$L_{\text{total}} = \lambda_E L_{\text{energy}} + \lambda_F L_{\text{forces}} + \lambda_S L_{\text{stress}} + \lambda_M L_{\text{magmom}}$$

where $\lambda$ values represent task-specific weighting coefficients optimized during training[3]. This approach ensures consistent predictions across all physical quantities while maintaining computational efficiency.

2.3 Training Dataset and Validation

The CHGNet model was trained on 1,580,395 structures from the Materials Project database, encompassing a broad range of elements[3],[4]. The training set includes diverse crystal systems, space groups, and chemical compositions to ensure broad applicability. Validation against DFT calculations demonstrates mean absolute errors of 29.8 meV/atom for energies and 0.076 eV/Å for forces[3].

3. CrystalNexus Implementation

3.1 System Architecture

CrystalNexus is implemented as a FastAPI-based web application with a JavaScript frontend utilizing the 3Dmol.js library for molecular visualization[5]. The backend integrates Pymatgen[6] for crystallographic data processing and CHGNet for property predictions. The system architecture follows a client-server model with RESTful API endpoints for data exchange.

3.2 Input Validation and Data Processing

The application implements rigorous validation protocols for Crystallographic Information File (CIF) inputs. Occupancy validation ensures all atomic sites possess full occupancy ($1.0 \pm 10^{-6}$), as partial occupancy structures are incompatible with the CHGNet training paradigm. Element validation restricts inputs to the elements supported by the selected model (86 for CHGNet).

3.3 Structure Optimization Protocol

Structure relaxation employs the LBFGS (Limited-memory Broyden–Fletcher–Goldfarb–Shanno) algorithm with force tolerance criteria of 0.01 eV/Å (the default, adjustable in Advanced Settings) and maximum iteration limits of 100 steps. The FIRE (Fast Inertial Relaxation Engine) algorithm remains available as a configurable alternative optimizer. The optimization simultaneously adjusts atomic positions and lattice parameters without space group constraints, allowing for complete structural relaxation to the nearest local energy minimum. Two convergence criteria are evaluated: a legacy criterion based solely on the maximum atomic force, and a criterion determined by the ASE optimizer itself, which also accounts for cell stress during cell relaxation and may therefore disagree with the force-only criterion. If a timeout (600 seconds by default) is reached before convergence, the best structure identified up to that point is returned.

3.4 Elastic Properties (Optional)

When the Calculate elastic properties switch under Analyze Structure is turned on, the elastic constants are evaluated after the relaxation, using the relaxed cell as the reference. Each of the six Voigt strain components is applied as a positive and a negative strain (default 0.25%; adjustable from 0.1 to 2.0% as Elastic strain (%) in Advanced Settings), giving 12 strained cells. The whole procedure is repeated at half the strain (24 strained cells in total, two passes) as a consistency check; the reported tensor is the one at the full strain. In each strained cell the ions are relaxed at fixed cell (force tolerance 0.001 eV/Å, at most 500 steps), and the 6×6 elastic tensor $C_{ij}$ (GPa) is obtained by central finite differences of the resulting stress with respect to strain. From $C_{ij}$, the Voigt, Reuss, and Hill averages of the bulk modulus $K$, shear modulus $G$, Young's modulus $E$, and Poisson's ratio $\nu$ are derived. Mechanical stability is judged by whether all eigenvalues of $C_{ij}$ are positive. The ion tolerance is deliberately tight: with soft modes the strain-induced forces can be below a loose threshold, which would skip the relaxation and give overestimated clamped-ion values. For materials with soft modes (e.g. ferroelectrics) a negative or unstable result is physically meaningful, so heed the mechanical-stability line and warning; values that change noticeably with the strain magnitude also suggest instability. The strain-consistency check compares the diagonal elements $C_{ii}$ at the two strains and warns when any differs by more than both 3 GPa and 5% of its value; this usually indicates a soft mode or an unstable material, so treat the tensor with caution. CHGNet's stress response varies with the strain magnitude for some materials, so its elastic constants are less reliable than those of MACE-MP-0. This works with both CHGNet and MACE-MP-0 (any model that provides stress).

Warnings are shown (and the calculation still runs) when the relaxation did not converge, the elastic calculation was aborted, the relaxation force tolerance is looser than 0.01 eV/Å (the strained cells would then start from an insufficiently relaxed reference), the ion relaxation in some strained cells did not converge, the results depend on the strain magnitude, or the structure is mechanically unstable.

Cost and scope. The calculation adds 24 strained-cell relaxations on top of the structure relaxation, and the time grows with the number of atoms, so a primitive or otherwise small cell is recommended. The cell is treated as a bulk crystal; the results are not meaningful for slabs, molecules, or structures containing vacuum.

Accuracy. Universal ML potentials trained on MPtrj tend to systematically soften elastic constants (underestimate them), so the values should be treated as estimates and trends rather than quantitative predictions. 4. User Interface and Workflow

Standard Analysis Workflow:

  1. Structure Input: Upload CIF files or select from curated sample structures
  2. Validation: Automated checks for occupancy completeness and element compatibility
  3. Supercell Generation: Optional expansion to larger unit cells (limited by total atom count)
  4. Structure Modification: Element substitution, atom deletion, and element insertion capabilities
  5. Property Prediction: ML-potential (CHGNet by default) calculation of energies and magnetic moments
  6. Results Analysis: Visualization of optimized structures and quantitative property data

4.1 Output Specifications

The application provides the following quantitative outputs:

  • Total Energy: System energy in electron volts (eV)
  • Energy per Atom: Normalized energy values for comparative analysis
  • Magnetic Moments: Atomic and total magnetic moments in Bohr magnetons ($\mu_B$)
  • Elastic Properties (optional): Young's modulus (Hill average) in the results, with the elastic tensor $C_{ij}$ (GPa), bulk/shear/Young's moduli and Poisson's ratio (Voigt, Reuss, Hill), and mechanical stability in the Details section, plus the elastic calculation time
  • Optimized Geometry: Relaxed atomic positions and lattice parameters
  • Computational Metrics: Calculation time and convergence statistics

4.2 Model Selection

The ML potential is chosen in the ML potential dropdown of the CIF loading dialog, before the structure is loaded, and stays fixed for that structure. The right-hand ML Potential panel shows the model read-only; to use another model, load the structure again (New CIF). Two models are available: CHGNet[3] (default; provides magnetic moments and site energies) and MACE-MP-0 (medium)[9] (MIT license; energy, forces and stress only, so magnetic-moment and site-energy fields are hidden). The element lists for substitution and insertion follow the chosen model, and a structure containing elements the model does not support is rejected at load time (the dialog stays open so another model can be chosen). The first MACE calculation downloads the model weights once (internet access is required). Both models are trained on the MPtrj dataset, but their absolute energies are not interchangeable: a loaded structure is never analyzed with more than one model. Results and exports name the model that produced them.

5. Advanced Structure Modification Algorithms

CrystalNexus provides sophisticated routines for modifying crystal structures, leveraging both geometric analysis and machine learning energy predictions.

5.1 Element Substitution and Deletion

Element substitution and atom deletion share the same "Edit Existing" workflow and can each be performed in two modes:

  • Manual Mode: Allows for deterministic replacement (or removal) of a specific atom at a user-selected site. This operation is implemented using Pymatgen to preserve the crystalline environment while updating the chemical species[6].
  • Auto (Optimal) Mode: Employs an exhaustive screening algorithm to identify the most energetically favorable substitution (or deletion) site for a target element. For a chosen source element type (e.g., oxygen), the system evaluates the energy $E$ of the structure with the operation applied at each valid site $i$:
    $$i^* = \text{arg min}_i \{ E(\text{Operation applied at site } i) \}$$
    Energy predictions are performed using the ML potential (CHGNet by default)[3]. Candidate sites are screened in batches of up to 8 per request (one native batched model call per batch, rather than one request per site), which keeps large sweeps responsive to cancellation: the search can be stopped mid-sweep with no partial operation applied, and a sweep is automatically aborted if it runs pathologically long.

Note: Clicking any atom directly in the 3D viewer—even while in Auto Mode—instantly switches to Manual Mode and selects that atom for modification.

5.2 Element Insertion

Element insertion facilitates the exploration of interstitial chemistry and defect properties through a dual-stage optimization process:

  • Manual Mode: Enables the addition of atoms at specific fractional coordinates $[x, y, z]$.
  • Auto (Optimal) Mode: Utilizes a hybrid geometric-energetic approach to identify stable interstitial positions:
    1. Geometric Void Detection: Potential insertion sites are identified via Voronoi tessellation analysis, then de-duplicated to symmetrically distinct voids using a local-environment fingerprint of each candidate site's neighbors[6]. This replaces Pymatgen's general-purpose VoronoiInterstitialGenerator, whose pairwise structure-matching for deduplication scales quadratically with candidate count and became impractically slow on larger supercells; the fingerprint approach scales linearly and returns the same sites.
    2. Energetic Stability Evaluation: Each candidate interstitial site is evaluated for thermodynamic stability using ML-potential energy predictions. The site yielding the lowest total energy is recommended as the optimal insertion point[3].

6. Limitations and Applicability

6.1 Model Limitations

CHGNet predictions are most reliable within the chemical and structural space of the training data. Extrapolation to extreme conditions, novel chemical environments, or structures significantly different from the Materials Project database may yield reduced accuracy[3]. Surface and defect calculations require careful validation against higher-level theoretical methods.

Recent research has identified systematic errors in CHGNet and other universal machine learning interatomic potentials, including systematic softening effects that lead to energy and force underprediction[8]. CHGNet exhibits a tendency to overestimate lattice constants and underestimate densities, which originates from the systematic biases present in the DFT training data and the sampling bias toward near-equilibrium atomic configurations in the training dataset.

6.2 Input Constraints

The current implementation restricts analysis to:

  • Fully occupied crystalline structures (occupancy = 1.0)
  • Elements within the training set (H-Ac)
  • File sizes below 10 MB
  • Total atom count ≤ 200 (configurable, to prevent excessive calculation times)

7. Performance Benchmarking

Computational performance analysis demonstrates typical calculation times of 2-30 seconds for systems containing 4-200 atoms, representing a 103-104 fold speedup compared to equivalent DFT calculations[3]. Memory requirements scale linearly with system size, enabling analysis on standard desktop hardware.

8. Data Export and Integration

Results may be exported in standard formats including CIF files for optimized structures, CSV files for numerical data (crystal information, atomic properties, stress tensor, trajectory data), and text files for energy and magnetic properties. This facilitates integration with existing computational workflows and enables subsequent analysis using specialized crystallographic software packages[7].

9. Conclusion

CrystalNexus provides an accessible platform for rapid crystal structure analysis using state-of-the-art machine learning methods. The integration of CHGNet enables materials researchers to perform high-throughput screening and property prediction tasks with minimal computational overhead while maintaining scientifically rigorous validation protocols.
